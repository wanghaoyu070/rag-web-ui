# 分块实验：从文档到证据

这是一份人工编写的 RAG 学习材料，用于观察分块、原文位置与重叠。它不是检索性能基准。实验代号 CHUNK-LAB-20261027。

## 固定字符：边界在哪里

固定字符切分按设定长度截取文本，之后向前滑动一个步长。步长等于片段长度减去重叠长度。即使刚好切在一句话中间，也会继续生成下一个片段。

观察任务：比较左右两栏，看看“步长”的定义和后面的解释是否位于同一个片段。判断切分效果时，不能只比较片段数量。

## 递归字符：优先保留段落

递归切分会尝试段落、换行和空格等边界。某段文本仍然过长时，继续使用更细的边界。在相同的长度限制下，片段的实际长度可能不同。

观察任务：开启“显示重叠”，检查实际重叠是否等于你填写的参数。参数是切分器使用的目标或约束，最终结果还会受到段落边界影响。

## 标题结构：章节之间的关系

标题结构切分先识别 Markdown 的井号标题，再在过长章节内递归切分。标题路径用于说明片段属于哪个章节，章节之间不增加重叠。

观察任务：选择本节中的片段，查看“对应原文”，再比较另一栏覆盖同一段文字的片段。标题路径属于元数据，不等于每个片段正文都包含完整标题。

## 原文定位：同一段内容如何对照

不同策略产生的第三个片段，通常并不对应原文中的同一位置。因此实验室使用字符范围关联左右片段，而不是按片段序号一一对应。

观察任务：选中一块比较长的片段，另一栏可能同时标出两块或更多片段。这说明相同原文范围在另一种策略中被分成了多个部分。

## 重叠比例：重复了多少内容

重叠有助于把边界附近的内容保留在相邻片段中，但也会增加重复文本与向量化成本。实验室按实际字符覆盖范围计算重叠比例。

观察任务：先使用500字符、50字符重叠，再修改为300字符、100字符重叠。重新生成后，比较片段数量、实际重叠比例和长度范围。

## 代码围栏：这些井号不是标题

下面的井号位于代码示例内部，不应产生新的章节。

```markdown
# 代码中的标题
## 仍然属于代码示例
```

观察任务：切换到标题结构策略，检查代码示例是否仍归属于本节。第一版只识别井号标题，不识别下划线式标题，也不自动识别普通文本中的章节名。

## 检索效果：统计指标不等于答案质量

较长片段可能包含更多上下文，也可能带来无关内容。较短片段更聚焦，但可能缺少条件和例外。片段少、平均长度短，都不能单独证明检索更好。

后续实验应固定向量模型、检索方式与 Top K，使用同一组问题比较是否召回了完整依据，再观察模型是否正确使用证据。

## 选择入库：只确认一个方案

对比阶段不生成向量。只有选择一个方案并确认入库后，系统才消费对应快照进行向量化。正式入库的片段文本、顺序和来源应与所选预览一致。

观察任务：选择标题结构方案入库，返回知识库后点击“查看片段”，核对策略名称、参数、数量以及快照一致性提示。
